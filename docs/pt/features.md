# ✨ Funcionalidades

* 🔑 **Armazenamento BYOK:** chaves de **site** (admin) e chaves **pessoais** opcionais (por usuário, opt-in) para **Gemini**, **Groq**, **DeepSeek** e qualquer endpoint **compatível com OpenAI**.
* 🪜 **Resolução pessoal → site:** o hub tenta a chave do próprio usuário primeiro, depois a de site, expondo um único resultado ao chamador.
* 🔀 **Ordem dos provedores sob seu controle:** o **administrador** arrasta os quatro provedores para a ordem em que são tentados, em uma página própria (*Ordem dos provedores*, com link nas configurações), e cada **usuário** pode arrastar a sua própria ordem em *Minhas chaves de IA*; um provedor que ficou fora de uma lista simplesmente segue atrás. O padrão é automático (Gemini, Groq, DeepSeek, compatível com OpenAI), então uma atualização não muda nada sozinha. As chaves pessoais continuam sendo tentadas antes das do site, qualquer que seja a ordem. O arrastar usa a lista ordenável do próprio Moodle, com caminho por teclado (Enter na alça e escolher para onde mover).
* 🧠 **Provedores com falha são lembrados:** quando um provedor esgota o tempo, está sobrecarregado, estourou a cota ou recusa a chave, ele é tentado **por último** por alguns minutos (configurável, 5 por padrão), em vez de toda requisição esperar por ele de novo. Uma falha que depende do pedido — um prompt grande demais, uma resposta bloqueada — não conta contra o provedor, e nada é removido da lista, então uma requisição não falha por causa da memória.
* 🧩 **Fachada de uma chamada:** `\local_aihub\ai::generate_text()` e `is_available()` — consumidas pelos plugins irmãos por dependência **soft** (`class_exists`), sem dependência dura.
* 🚫 **Não embrulha o `core_ai`:** cada consumidor mantém o próprio fallback para `core_ai`, então um site que já tem `core_ai` configurado **não precisa de nada extra** — o hub continua opcional.
* 👁️ **Chaves pessoais write-only:** uma vez salva, a chave pessoal **nunca é devolvida ao navegador** — a página mostra só o status *configurada / não configurada*, fechando a leitura via *Entrar como*.
* 🧑‍💻 **Página self-service:** *Minhas chaves de IA* (nas preferências do usuário) para adicionar/substituir/remover chaves pessoais e revisar o próprio uso recente.
* 📊 **Relatório de uso para o admin:** todas as chamadas a provedores atendidas pelas **chaves do site**, de todos os usuários, com filtros de **somente falhas** e **somente sucessos** e download **CSV / Excel** — protegido por `local/aihub:viewusage`.
* 🛡️ **Guard SSRF:** o endpoint compatível com OpenAI configurável é forçado a HTTPS, com bloqueio de loopback / link-local / faixas privadas e anti-rebinding de DNS A/AAAA.
* 🧾 **Log de uso + task de retenção:** uma linha por **chamada a provedor**, não por requisição (usuário, componente solicitante, o que foi gerado, provedor, modelo, tier da chave, situação e — quando falhou — o motivo dado pelo próprio provedor), e uma task agendada que limpa logs além de uma retenção configurável. Uma requisição que cai para outro provedor deixa portanto uma linha para cada um, de modo que uma chave que nunca funciona não consegue se esconder atrás daquela que respondeu.
* 🔒 **Privacidade completa:** Privacy provider completo para o log de uso e as preferências pessoais, com os destinos externos declarados.
